ეს არის Noepedia Experiment 002 — structured relation-field run.

გამოიყენე მხოლოდ ქვემოთ მოცემული სტრუქტურული მონაცემები.

არ გამოიყენო გარე ცოდნა ელექტრონიკის შესახებ იმის დასადგენად, „როგორ უნდა იყოს ჩვეულებრივ სქემაში“. Human-readable labels მხოლოდ საჩვენებელია და მათგან დამატებითი ცოდნა არ გამოიტანო.

ამ ექსპერიმენტში წინა ცდის ორი ნაკლი უკვე explicit structure-ადაა წარმოდგენილი:

1. connector-ს აქვს terminal/pin granularity;
2. EXPOSES_NET და CONNECTED_TO შორის consistency rule explicit-ადაა მოცემული.

მნიშვნელოვანი წესები:

1. არ ჩათვალო, რომ ყველა stored relation სწორია.
2. არ დაამატო ახალი evidence.
3. არ დახურო OPEN მხოლოდ იმიტომ, რომ target task გადაწყდა.
4. მკაფიოდ გამოყავი:
   - stored facts;
   - rule application;
   - inference;
   - unresolved structure.
5. ააწყე ყველაზე პატარა task-specific cut.
6. mismatch მხოლოდ მაშინ გამოაცხადე ფორმალურად დასაბუთებულად, თუ explicit relation + explicit rule ამის საშუალებას იძლევა.
7. თუ field-ში კიდევ აკლია structural constraint, ცალკე დააფიქსირე როგორც ახალი unresolved requirement.
8. revision-ისას შეცვალე მხოლოდ მინიმალურად აუცილებელი relation.
9. provenance, status და revision history არ გააქრო.
10. არ გამოიყენო წინა ექსპერიმენტების ცოდნა.

Operational reading of the explicit rule:

For an object of type terminal:

If

T → EXPOSES_NET → X

then the field requires

T → CONNECTED_TO → X

for that same terminal and the same net.

If the stored CONNECTED_TO target differs from X,
the two relations are structurally inconsistent under RULE_TERMINAL_EXPOSE_CONNECT.

This operational reading is part of the supplied field definition and is not external evidence.

OPEN_01:

U1 → ENABLE_CONTROLLED_BY → EN_PATH

status: open
provenance: SRC_FIXTURE

constraint:
No relation in the current target task supplies evidence about EN_PATH.

TARGET TASK

1. Build the smallest task-specific cut needed to check the consistency of J2_P1.
2. Apply only explicit rules contained in the supplied field.
3. Determine whether any relation is formally inconsistent.
4. If a mismatch exists:
   - identify it;
   - show the exact explicit rule path that makes it a mismatch;
   - propose the smallest revision.
5. State whether the revision is:
   - logically required by the supplied field,
   - merely a coherence preference,
   - or still conditional.
6. Preserve OPEN_01 unless the supplied field gives evidence that resolves it.
7. Check whether any additional structural requirement is still missing.
8. State exactly which relations would change and which would remain untouched.

OUTPUT FORMAT

A. Smallest task-specific cut
B. Explicit reconstruction
C. Rule application path
D. Formal mismatch, if any
E. Minimal revision
F. Status of the revision: required / conditional / optional
G. OPEN_01 after the task
H. Directly stored facts used
I. Rule-derived consequences
J. Other inference
K. Remaining structural uncertainty / new OPENs
L. Relations changed
M. Relations explicitly untouched
N. Final compact verdict
