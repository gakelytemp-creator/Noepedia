# IDEAL_TO_REAL — იდეალური სამყაროდან გარეთ

**Status: CURRENT + WORKING HYPOTHESIS**  
**Date: 2026-10-15**

## 0. მთავარი შემობრუნება

Noepedia-ში ცოდნის მოძრაობა მხოლოდ ერთი მიმართულებით არ მიდის.

აქამდე ბუნებრივი სურათი იყო:

~~~text
REAL
→ contact / projection
→ concepts
→ field
→ ideal construction
~~~

მაგრამ შიდა კონსტრუქციულ სამყაროს შეუძლია თვითონ წარმოქმნას ისეთი მოთხოვნა,
რომლის შესაბამისი რეალურ სამყაროში ჯერ არც ნაპოვნია და შეიძლება საერთოდ არც იყოს
შექმნილი.

ამიტომ მეორე, თანაბრად მნიშვნელოვანი მოძრაობაა:

~~~text
IDEAL
→ construction
→ structural need
→ abstract concept object
→ search / query / measure / trap / design
→ REAL
~~~

ეს მეორე მოძრაობა არ არის პირველი გზის უბრალო „უკან დაბრუნება“.

> **ზვავის საწყისი შეიძლება პირდაპირ იდეალურ სამყაროში გაჩნდეს.**

## 1. რატომ არის შიდა სამყარო „იდეალური“

„იდეალური“ აქ არ ნიშნავს სრულყოფილს ან რეალობისგან დამოუკიდებელ ფანტაზიას.

იგი ნიშნავს, რომ შიდა კონსტრუქცია შეიძლება დაეყრდნოს ისეთ **განყენებულ,
ფუნდამენტალურ ცნებებსა და კანონებს**, რომლებიც რეალურ სამყაროში ყოველთვის
შერეული, ხმაურიანი და კონკრეტული მატარებლებით გვხვდება.

მაგალითად შიგნით შეიძლება იმუშაოს:

~~~text
ადგილი
რიგი
ზომა
ნაწილი / მთელი
იგივეობა
მიზეზობრივი მიმართულება
შესაძლებლობა
უარყოფა
~~~

და ამ სუფთა კავშირებით ააგოს სტრუქტურა მანამდე, სანამ კონკრეტული გარე მატარებელი
დადგინდება.

ამიტომ შიდა სამყარო არა მხოლოდ მიღებული რეალობის შეკუმშული ასლია.

> **მას შეუძლია ისეთი სტრუქტურის აგება, რომლის გარე რეფერენტი ჯერ საძებნია ან ასაგებია.**

## 2. განყენებული ცნების ობიექტი — ACO

**Abstract Concept Object (ACO) / განყენებული ცნების ობიექტი** არის შიდა
კონსტრუქციის მიერ დაბადებული მისამართიანი ობიექტი, რომელსაც ჯერ არ აქვს დადგენილი
გარე რეფერენტი, მაგრამ უკვე აქვს იმდენი ბმა და შეზღუდვა, რამდენიც ამოცანის
გაგრძელებას სჭირდება.

მარტივი სახე:

~~~text
A ──requires──> X
X ──must_fit──> B
X ──before────> C
X ──has────────> P
~~~

აქ `X` ცარიელი ადგილი აღარ არის.

იგი უკვე **სტრუქტურულად დატვირთული ობიექტია**.

შეიძლება ჯერ არ ვიცოდეთ:
- რა ჰქვია;
- სად არის;
- არსებობს თუ არა;
- ერთია თუ რამდენიმე;
- უნდა ვიპოვოთ თუ უნდა ავაგოთ.

მაგრამ უკვე ვიცით, **რა ურთიერთობებში უნდა ჩაჯდეს**.

## 3. OPEN და ACO ერთი რამ არ არის

### OPEN

ამბობს:

> აქ რაღაც დაუხურავია.

### ACO

ამბობს:

> ჯერ არ ვიცი რა ხარ, მაგრამ უკვე ვიცი იმდენი შენს შესახებ,
> რომ შეიძლება შენი ძებნა, განსხვავება ან აგება დავიწყო.

ამიტომ ACO არის **ფორმირებული უცნობი**.

OPEN შეიძლება საერთოდ უშინაარსო იყოს:

~~~text
A → ? → B
~~~

ACO კი უკვე მოთხოვნებითაა შემოსაზღვრული:

~~~text
ACO_X
├─ must_be_in: REGION_R
├─ must_support: LOAD_L
├─ must_precede: EVENT_C
└─ must_not_conflict_with: RULE_Q
~~~

## 4. ACO-ს კანდიდატთა სივრცე

ACO-ს გარე შესაბამისი თავიდან შეიძლება მრავალი იყოს.

~~~text
Cand(ACO_X) = {a, b, c, d, ...}
~~~

ყოველი ახალი შიდა ან გარე შეზღუდვა ამ სივრცეს ცვლის:

~~~text
constraint₁
→ {a, b, c, d}

constraint₂
→ {a, c, d}

constraint₃
→ {c}
~~~

აქ მთავარი არაა წინასწარ ალბათობის მიწერა.

მთავარია, რომ სისტემა პატიოსნად ინახავდეს:
- რომელი კანდიდატებია ჯერ დასაშვები;
- რის გამო გამოირიცხა თითოეული;
- რომელი შეზღუდვაა შიდა;
- რომელი მოვიდა გარე კონტაქტიდან;
- რომელი ჯერ მხოლოდ ჰიპოთეზაა.

## 5. binding — როცა შესაბამისი მოიძებნა

თუ საბოლოოდ ერთი ან რამდენიმე გარე ობიექტი აკმაყოფილებს ACO-ს მოთხოვნებს,
ACO **არ ქრება**.

ამის ნაცვლად იწერება კავშირი:

~~~text
ACO_X ──realized_by / bound_to──> REAL_OBJECT_731
~~~

ეს მნიშვნელოვანია, რადგან უნდა დარჩეს განსხვავება:

~~~text
რას ვეძებდით
≠
რა ვიპოვეთ
~~~

თუ ნაპოვნი ობიექტი მხოლოდ ნაწილობრივ შეესაბამება მოთხოვნას, ეს განსხვავებაც
მისამართიანი რჩება.

ACO-ს შენარჩუნება გვაძლევს:
- ძიების provenance-ს;
- დიზაინის მოთხოვნის ისტორიას;
- ალტერნატიული რეალიზაციების შედარებას;
- იმ პირობების ცოდნას, რომლებშიც binding უნდა REOPEN-დეს.

## 6. ორი გარე გზა — აღმოჩენა და გამოგონება

ACO-ს გარეთ გასვლა ორ ძირითად რეჟიმად იყოფა.

### 6.1 SEARCH — „იპოვე ის, რაც უკვე არსებობს“

~~~text
ACO
→ candidate search
→ observation / retrieval / measurement
→ compare with constraints
→ BIND or remain OPEN
~~~

ეს არის აღმოჩენის რეჟიმი.

### 6.2 DESIGN — „თუ არ არსებობს, ააგე“

~~~text
ACO
→ no adequate external match
→ treat constraints as design target
→ construct candidate
→ test
→ realized_by
~~~

ეს არის ინჟინერული რეჟიმი.

ერთი და იგივე ACO-ს შეუძლია ჯერ SEARCH სცადოს და მერე DESIGN-ზე გადავიდეს.

მაგალითად:

~~~text
მჭირდება რაღაც, რაც:
- ამ სივრცეში ჩაეტევა
- ამ დატვირთვას დაიჭერს
- ამ მიმართულებით იმოძრავებს
- ამ შეზღუდვას არ დაარღვევს
~~~

სისტემა ჯერ შეიძლება ეძებდეს მზა დეტალს.
თუ ვერ იპოვა, იგივე განყენებული ობიექტი ხდება **დიზაინის სამიზნე**.

## 7. active learning — რას ვკითხოთ გარეთ

თუ ACO-ს რამდენიმე კანდიდატი დარჩა, შემდეგი კონტაქტი შემთხვევითი არ უნდა იყოს.

სისტემა უნდა ეძებდეს:

> **რომელი დაკვირვება ან კითხვა ყველაზე მეტად შეამცირებს დარჩენილ თავისუფლებას?**

მაგალითად:

~~~text
Cand(X) = {A, B, C, D}

query Q:
A,B → YES
C,D → NO
~~~

ასეთი კითხვა კანდიდატთა სივრცეს ძლიერად ყოფს.

ამით მიიღება ციკლი:

~~~text
IDEAL:
რომელი ACO არის დასაზუსტებელი?
        ↓
რომელი თვისება ყველაზე მეტად განასხვავებს კანდიდატებს?
        ↓
OUTWARD QUERY / MEASURE / SEARCH
        ↓
REAL CONTACT
        ↓
ახალი constraint
        ↓
IDEAL UPDATE
~~~

ეს არის active learning-ის არქიტექტურული ადგილი Noepedia-ში.

## 11. ACO-ს სამუშაო lifecycle

პირველი სამუშაო სტატუსები:

~~~text
ABSTRACT
  ↓
SEARCHING
  ├─→ BOUND
  ├─→ PARTIAL_BIND
  └─→ DESIGN_TARGET
          ↓
       PROTOTYPE
          ↓
       TESTED_BIND
~~~

მნიშვნელობები:

- **ABSTRACT** — მხოლოდ შიდა მოთხოვნებით არსებობს;
- **SEARCHING** — გარე შესაბამისებს ეძებს;
- **BOUND** — გარე შესაბამისი დადგენილია საჭირო scope-ში;
- **PARTIAL_BIND** — შესაბამისობა ნაწილობრივია;
- **DESIGN_TARGET** — არსებული შესაბამისი ვერ მოიძებნა ან განზრახ ასაგებია;
- **PROTOTYPE** — დიზაინიდან რეალურ კანდიდატად გამოვიდა;
- **TESTED_BIND** — bridge/certificate-ის ფარგლებში დამოწმებულია.

ეს ჯერ მონაცემთა საბოლოო სქემა არაა.

ამ მექანიზმით ერთი და იგივე სისტემა პასუხობს ორ დიდ კითხვას:

> **რა არის?**

და

> **რა უნდა არსებობდეს, რომ ეს კონსტრუქცია გაგრძელდეს?**

პირველი უფრო ხშირად რეალურიდან იდეალურისკენ მოდის.

მეორე შეიძლება მთლიანად იდეალურ სამყაროში დაიბადოს და იქიდან გავიდეს გარეთ.

ამიტომ Noepedia-ს აქტიური ნაწილი აღარ არის მხოლოდ აღწერა ან რეკონსტრუქცია.

> **იდეალურ სამყაროს შეუძლია რეალური სამყაროსთვის მოთხოვნის წარმოქმნა.**

## 13. მკაცრი საზღვრები

ACO-ს არ აქვს უფლება:
- საკუთარ თავს გარე ობიექტად გამოაცხადოს;
- candidate = 1 ავტომატურად truth-ად ჩათვალოს bridge/certificate-ის გარეშე;
- SEARCH failure = nonexistence ჩათვალოს;
- DESIGN_TARGET = physically possible ჩათვალოს აგებითი და გარე შემოწმების გარეშე;
