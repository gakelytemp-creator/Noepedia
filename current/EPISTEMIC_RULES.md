# EPISTEMIC_RULES — რა როგორ მოწმდება

**Status: CURRENT**  
**Date: 2026-10-14**

Noepedia-ში ყველა მტკიცება ერთი ტიპის შემოწმებას არ ითხოვს.

## 1. სამი ეპისტემური რეჟიმი

### 1.1 კონტაქტური შემოწმება

გამოიყენება მაშინ, როცა კითხვა რეალურ სამყაროს ეხება.

მაგალითები:
- კომპრესორი რეალურად რამდენ ხანს აგვიანებს გამორთვას;
- პროგრამა კონკრეტულ სიტყვას რას ამთხვევს;
- სენსორი რა მნიშვნელობას აბრუნებს.

შემოწმება:
- დაკვირვება;
- გაზომვა;
- გაშვება;
- მოქმედების შედეგი;
- სხვა პირდაპირი კონტაქტი.

### 1.2 კონსტრუქციული შემოწმება

გამოიყენება შიდა იდეალურ სამყაროში.

კითხვის ფორმაა:
> მოცემული კანონებით ეს შეიძლება აიგოს?

შემოწმება:
- გამოყვანადობა;
- შიდა წინააღმდეგობა;
- დამოუკიდებელი გზების თანხვედრა;
- ანალიზი ↔ სინთეზის აღდგენა;
- შეზღუდვების გავრცელება;
- უარყოფის ძლიერი ტოტის გავლა.

აქ გარე ექსპერიმენტი ყოველ ნაბიჯზე საჭირო არ არის.

### 1.3 ხიდური შემოწმება

ამოწმებს არა მხოლოდ შიდა კანონიერებას, არამედ კითხვას:

> ეს შიდა კონსტრუქცია რომელი თვისებებით და რა არეში შეესაბამება რეალურ ობიექტს?

ამის ინსტრუმენტია **semiotic cut / certificate**.

## 2. semiotic cut / certificate

ხიდის ჩანაწერმა უნდა თქვას მინიმუმ:

- რომელი შიდა კონსტრუქციაა;
- რომელ რეალურ წყაროს/ობიექტს უკავშირდება;
- რომელი თვისებებია შემოწმებული;
- რა მეთოდით;
- რა პირობებში;
- რა დიაპაზონში;
- როდის;
- რა არ არის შემოწმებული.

ამის შემდეგ შიდა აგება შეიძლება გაგრძელდეს ამ არეში ხელახალი გარე გაზომვის გარეშე.

როცა კონსტრუქცია სერტიფიკატის საზღვარს სცდება, ჩნდება **BRIDGE_LIMIT**.

## 3. PASS-ის მნიშვნელობა

PASS არ ნიშნავს ავტომატურად ჭეშმარიტებას.

მისი ზუსტი მნიშვნელობა დამოკიდებულია რეჟიმზე:

- CONTACT_PASS — კონკრეტული გარე შემოწმება გაიარა;
- CONSTRUCTIVE_PASS — მოქმედ კანონებთან თავსებადია;
- BRIDGE_PASS — შესაბამისობის სერტიფიკატი მოცემულ არეში მოქმედებს.

ერთი კლასის PASS მეორე კლასს არ ანაცვლებს.

## 4. OPEN

OPEN არის მისამართიანი დაუხურავი მდგომარეობა.

იგი შეიძლება იყოს:

- UNKNOWN — მნიშვნელობა/ობიექტი უცნობია;
- AMBIGUOUS — რამდენიმე კანდიდატია;
- STRUCTURE_OPEN — საჭირო ბმა/სტრუქტურა აკლია;
- SEARCH_OPEN — გზა შეიძლება არსებობდეს, მაგრამ ჯერ ვერ მოიძებნა;
- BRIDGE_LIMIT — შესაბამისობის საზღვარს მივადექით;
- CONFLICT — ორი აქტიური სტრუქტურა ერთმანეთს ეწინააღმდეგება;
- OPEN_BY_DESIGN — სისტემა განზრახ არ აფორმალიზებს.

OPEN არ ნიშნავს შეცდომას და არ ნიშნავს უარყოფას.

## 5. BLOCKED

BLOCKED უნდა იყოს მიზეზიანი.

არასაკმარისია მხოლოდ:
> ვერ გავაგრძელე.

უნდა ეწეროს, რატომ:
- კანონი კრძალავს;
- სტრუქტურა აკლია;
- კანდიდატები ორაზროვანია;
- ძებნა არ დასრულებულა;
- ხიდის მოქმედების არე დასრულდა;
- სხვა პლასტში კონფლიქტი გაჩნდა.

„ვერ ვიპოვე“ ≠ „არ არსებობს“.

## 6. უარყოფის გზა

ნებისმიერი ძლიერი შიდა მტკიცება უნდა ექვემდებარებოდეს არა მხოლოდ მხარდამჭერ აგებას,
არამედ მისი უარყოფის ყველაზე ძლიერ შესაძლო ტოტსაც.

~~~text
CLAIM
├─ build as true
└─ build as false / alternative
~~~

წინააღმდეგობამდე მისული ტოტი იკვეთება.

ეს წესი იცავს სისტემას მხოლოდ მხარდამჭერი გზების შეგროვებისგან.

## 7. REOPEN

REOPEN ნიშნავს, რომ უკვე გამოყენებული სტრუქტურა ხელახლა ხდება პრობლემური.

REOPEN არ შლის ისტორიას.

ინახება:
- ძველი ფორმულირება;
- მისი მოქმედების არე;
- რა ახალმა აცდენამ გახსნა;
- ახალი კანდიდატები;
- დამოკიდებული სტრუქტურები, რომლებსაც გადახედვა სჭირდება.

## 8. ორი საათის წესი

ყოველ მნიშვნელოვან შიდა ჩანაწერს უნდა შეეძლოს პასუხი ორ კითხვაზე:

1. ბოლოს როდის ჰქონდა რეალურ სამყაროსთან შესაბამისი კონტაქტი?
2. ეს ჩანაწერი გარეთ უკვე განხორციელებულია/დამოწმებულია თუ ჯერ მხოლოდ შიდა კონსტრუქციაა?

ეს განსაკუთრებით მნიშვნელოვანია გენერაციული ცენტრებისთვის.

## 9. false settled არის განსაკუთრებული დაზიანება

Noepedia-ში OPEN ხშირად უკეთესია, ვიდრე არასწორი დახურვა.

ამიტომ recognition/ingest პროცესში უნდა განსხვავდებოდეს:

- CORRECT_MATCH;
- AMBIGUOUS;
- UNKNOWN;
- FALSE_MATCH;
- SILENT_MISS.

პრინციპი:

> **სისტემას ურჩევნია პატიოსნად ვერ შეჭამოს, ვიდრე არასწორად მოინელოს.**

## 10. ნარატიული და კონსტრუქციული თანხმობა

შეთანხმებულად ჟღერადი ტექსტი არ უდრის კანონიერად აგებულ სტრუქტურას.

ამიტომ:

> **Narrative coherence ≠ constructive coherence.**

LLM-ის ტექსტი შეიძლება იყოს კანდიდატის გენერატორი.
კონსტრუქციული სტატუსი უნდა მოდიოდეს მისამართიანი სტრუქტურისა და შესაბამისი
შემოწმების რეჟიმიდან.

## 11. სტატუსის მინიმალური ჩანაწერი

სასურველი ჩანაწერი შეიცავს:

~~~text
claim / structure
source
author
mode: CONTACT | CONSTRUCTIVE | BRIDGE
status
scope
timestamp
dependencies
certificate / cut if any
OPEN / BLOCKED reason if any
reopen condition
~~~

ეს არის სამუშაო კონტრაქტი და არა საბოლოო მონაცემთა სქემა.
