## 2. არქიტექტურა

```
WORLD_INPUT.md (ტექსტი)
   ↓  [ერთადერთი არამანქანური ნაბიჯი: ტექსტი → rule record. აუდიტირებადი მონაცემი]
rule records ქსელში (TYPE=RULE, მისამართიანი, CURRENT/HISTORICAL)
   ↓
generic_evaluator.py (ერთი, content-blind: არ იცნობს არც P1-ს, არც VIS-ს)
   ↓
demon_core.py (უცვლელი — GW02-ის კომიტი 51581c1)
```

წესის ჩანაწერის ენა — მინიმალური ტიპების ლექსიკონი (წინასწარი ჰიპოთეზა):

| ტიპი | GW01-ში ფარავს |
|---|---|
| CARDINALITY_POLICY (პრედიკატზე) | R1 |
| DERIVATION (premises-პატერნები ცვლადებით ⇒ დასკვნა + provenance) | R2, R3 |
| TEMPORAL_POLICY (გვიანი TIME აძევებს → HISTORICAL) | R5 |
| INGEST_GUARD (პირობა-პატერნი ⇒ აკრძალული პატერნი წყაროს კლასზე) | R4 |
| CLOSURE_POLICY (არარსებობა ≠ უარყოფა) | R6 |
| INVARIANT (პატერნი უნდა დარჩეს CURRENT) | C1 |

Evaluator-ის უფლება მხოლოდ: პატერნის მორგება ცვლადებით (X, Y), სტატუსის query,
შედარება, და demon_core-ის პრიმიტივების გამოძახება. წესის სახელი კოდში არ ჩნდება.

## 3. მეთოდი

1. R1–R6 + C1 ითარგმნება rule record-ებად; თარგმანი ფაილშია (RULES_GW01.py
   ან .json) — ცალკე, წაკითხვადი, თითო ჩანაწერს WORLD_INPUT-ის ციტატა ახლავს.
2. gw03_runner.py შეიცავს **მხოლოდ მოვლენებს** E1–E12 (რა შემოვიდა, რა იკითხეს).
   წესის სემანტიკა runner-ში = 0 სტრიქონი. ეს grep-ით მოწმდება:
   `grep -c "R[1-6]\|C1" gw03_runner.py` → მხოლოდ კომენტარები/მისამართები.
3. გაშვება E1–E12 → დიფი GW01_RUN_LOG.txt-თან (GW02-ის მექანიკური ლოგი).
4. ყოველი განსხვავება იარლიყდება: **ENCODER_HOLE** (ტექსტი ჩანაწერს ვერ
   განსაზღვრავს ცალსახად — ეს არის compiler boundary-ის გაზომვა) /
   **EVALUATOR_ERROR** (ჩემი კოდის შეცდომა) / **SEMANTIC_BY_NATURE**.
   წარმატება = ნული უიარლიყო განსხვავება.

## 4. დალუქული პროგნოზები

1. **E1–E12 სრულად რეპროდუცირდება** (ვერდიქტები, STOP-რუკა, საბოლოო რეესტრი
   იდენტური GW02-ის ლოგისა), runner-ში წესის არც ერთი სპეციალური განშტოების გარეშე.
2. **ტიპების ლექსიკონი საკმარისია ≤6 ტიპით** (§2-ის ცხრილი ან მცირე კორექციით);
   evaluator ≤250 სტრიქონი, demon_core უცვლელი.
3. **R4 ყველაზე ძვირი იქნება**: მის დეკლარირებას დასჭირდება ის, რაც სხვებს არა —
   პირობა **სხვა ჩანაწერის მიმდინარე სტატუსზე** (მეტა-მითითება). ვპროგნოზირებ
   ≥1 ENCODER_HOLE-ს ზუსტად R4-ზე: ტექსტი ცალსახად არ ამბობს, R4-ის პირობა
   როგორ იქცევა, როცა (O4 P3 ?) multiplicity-OPEN-შია.
4. **E9-ის ორმაგი გაჩერება (BLOCK + NEED) evaluator-იდან თავისით ამოვა**:
   applicability-შეფასება E8-ის OPEN-ს წააწყდება და მეორე STOP-ს წესების
   მექანიკიდან დააგენერირებს — ისე, რომ ეს კავშირი არსად იყოს ხელით ჩაწერილი.
   (GW02-ში ეს runner-ის ორი ხელით დაწერილი if იყო; აქ უნდა გაქრეს.)
5. **წესი-როგორც-ჩანაწერი ერთ ადგილას მაინც მოგვცემს რამეს უფასოდ**: მინიმუმ —
   E9-ის მეორე STOP-ის BASIS-ად თვითონ R4-ჩანაწერის მისამართი დაიდება, ანუ
   „რატომ გავჩერდი" პასუხი ქსელშივე იქნება მიკვლევადი REFERS_TO-თი.
